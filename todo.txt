  1. How the Subscription Financial Year Works in Code
  The system follows the Indian Financial Year (April 1 to March 31).

  In subscription_payment.go (Lines 43–50):
    func getMembershipYearEnd(now time.Time) time.Time {
        year := now.Year()
        if now.Month() >= 4 { // April to Dec
            return time.Date(year+1, 3, 31, 23, 59, 59, 0, now.Location())
        }
        // Jan to March
        return time.Date(year, 3, 31, 23, 59, 59, 0, now.Location())
    }
  • If someone subscribes on October 8, 2026, their subscription end date is set to
  March 31, 2027.
  • If someone subscribes on May 10, 2027, their subscription end date is set to March
  31, 2028.
  • This dynamic calculation is fully future-proof and will work correctly for 2027,
  2028, 2029, and beyond.

  2. The 2-Month Grace Period (April 1 to May 31)
  In member_auth.go (Lines 68–71):
  • When March 31 arrives, the member's subscription does not instantly cut off.
  • The system adds a 2-month grace window:
    graceEnd := sub.EndDate.AddDate(0, 2, 0) // April & May
    if now.Before(graceEnd) || now.Equal(graceEnd) {
        return true // Member is still treated as PAID during April & May
    }

  • In taga-api/service/renewal_reminder.go:
      • April 1: System sends Reminder 1 ("New membership year started").
      • April 15: System sends Reminder 2 ("Mid-month reminder").
      • May 1: System sends Reminder 3 ("Final reminder before grace ends").
  • On June 1: The grace period ends. The member automatically becomes Unpaid (isPaid:
  false) if they haven't renewed.

  3. What Happens in Future Years: ⚠ 2 CRITICAL GAPS FOUND
  While the online Razorpay flow is future-proof, here are two vulnerabilities in the
  current code that will cause issues in future years:

  ⚠ Issue 1: The 52 "Offline Paid" Members in members.json Have NO Year or Expiry     
  Date!
  In data/member/members.json, members have:
    {
      "name": "Murugan",
      "payment_status": "Paid",
      "subscription_active": true
    }

  There is no year attached to this flag!

  • In admin_members.go (Line 1885):
    if strings.EqualFold(pStatus, "Paid") {
        return "Paid"
    }
  • What happens next year (April/June 2027)?
  Because there is no expiration timestamp in members.json, these 52 members will
  remain "Paid" forever unless an admin manually goes into the dashboard and toggles
  each one back to "Unpaid"!

  ⚠ Issue 2: Concurrency Bug on member_subscriptions.json During Renewals
  When many members pay their renewal on April 1st:
  • member_subscriptions.json uses raw os.ReadFile and os.WriteFile without a sync.
  Mutex lock in taga-api/handler/subscription_payment.go:680.
  • If 2 or more members pay online at the exact same second, one transaction can
  overwrite and wipe out the other member's record.

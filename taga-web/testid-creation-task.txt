Analyze the Node.js web application in the current directory and automatically add data-testid attributes to all key UI elements needed for Selenium test automation in Go.

Requirements:

1. SCAN the entire project for the following user interaction elements:
   - Login form elements (email/username input, password input, submit button)
   - Registration form elements
   - Form submission elements (text inputs, textareas, select dropdowns, submit buttons)
   - Navigation elements (menus, links, buttons that change routes)
   - CRUD operation elements (create, read, update, delete buttons/forms)
   - Modal dialogs and their action buttons

2. For each identified element, ADD data-testid attributes with the following naming convention:
   - Input fields: `testid-{formName}-{fieldName}-input`
   - Buttons: `testid-{action}-button`
   - Links: `testid-{destination}-link`
   - Forms: `testid-{formName}-form`
   - Error/success messages: `testid-{type}-message`
   - Modals: `testid-{modalName}-modal`

   Examples:
   - Login email field: `data-testid="login-email-input"`
   - Login password field: `data-testid="login-password-input"`
   - Login submit button: `data-testid="login-submit-button"`
   - Registration form: `data-testid="register-form"`
   - Delete confirmation button: `data-testid="delete-confirm-button"`

3. UPDATE all relevant template files (JSX, EJS, Pug, HTML, Vue, React components) by injecting these testId attributes without breaking existing functionality.

4. GENERATE a manifest file named `test-ids-manifest.json` in the project root that includes:
   - List of all added test IDs
   - Their locations (file path and line number)
   - The element type they belong to
   - The user flow they support (login, registration, form submission, etc.)

5. PRESERVE all existing classes, IDs, and other attributes - only add the new testId attributes.

6. SKIP adding test IDs to third-party libraries, node_modules, or build output directories.

7. For dynamic elements generated by JavaScript, add comments in the code showing where test IDs should be injected.

The goal is to prepare the application for Selenium automation tests written in Go using the standard testing package and tebeka/selenium driver.

After completion, provide a summary of:
- Total elements modified
- Number of test IDs added by category
- Any manual intervention needed
- Recommended Selenium selectors for each identified user flow
- Provision a way to find the elements without testId
